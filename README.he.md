## מה זה

Plux היא אפליקציית ניהול פיננסי אישי שנבנתה מקצה לקצה כפרויקט פורטפוליו — לא שכפול של מוצר קיים, ולא מוצר מסחרי. השאלה שממנה זה יצא הייתה פשוטה: הבנקים וחברות האשראי בישראל מראים לך *מה קרה*; כמעט שום דבר לא נותן לך *לשאול* על זה בשפה חופשית ולקבל תשובה אמיתית, מחושבת מהנתונים שלך. Plux עושה בדיוק את זה.

האפליקציה כולה בעברית, RTL מקצה לקצה, ובנויה סביב איך שהבנקאות הישראלית באמת עובדת — מחזורי חיוב של כרטיסי אשראי שלא מתיישרים עם החודש הקלנדרי, הוראות קבע, ומשקי בית עם כמה חשבונות.

## אפשר לנסות בלי חשבון

הרשמה רק כדי להציץ באפליקציית פיננסים היא חסם מיותר, אז ל-Plux יש נתיב דמו ייעודי: משתמש [Clerk](https://clerk.com/) אמיתי, עם ארבעה חודשים של תנועות סינתטיות ריאליסטיות (לגמרי מומצאות — אין שם שום נתון פיננסי אמיתי) על פני קניות, שכר דירה, מנויים, העברות ועוד. לחיצה אחת במסך הבית, מגובה בזרימת sign-in token של Clerk, ואתם מול דשבורד מלא נתונים.

## יכולות

- **בית** — נטו, הכנסות והוצאות של החודש הנוכחי במבט אחד, יתרה עדכנית בחשבון, ותחזית לסוף החודש (רצפה / צפוי / תקרה) עם מדד ביטחון, וגם טיקר שוק חי.
- **Pluxer** — עוזר צ'אט מבוסס AI (Claude) שעונה על שאלות כמו *"כמה נשאר לי החודש?"* על ידי שאילתה אמיתית על התנועות, התקציבים והקטגוריות שלכם דרך tool-calling — לא ניחוש מתוך פרומפט. הוא גם כותב לבד סיכום קצר בשפה טבעית לכל חודש.
- **תנועות** — היסטוריית תנועות עם חיפוש, סינון, שיוך לקטגוריות וזיהוי תנועות לא מסווגות.
- **הוראות קבע ומנויים** — מבחין בין חיובים שהוצהרו במפורש כהוראת קבע לבין כאלה שהמערכת מזהה אלגוריתמית (עם ציון ביטחון), ומחזה מה עוד צפוי להיכנס עד סוף החודש.
- **תקציב ויעדי חיסכון** — הגדרת יעדי הוצאה לפי קטגוריה ומעקב אחרי יעדי חיסכון.
- **ייבוא** — ייבוא דפי חשבון/כרטיס אשראי.
- **"חודש פיננסי" אמיתי** — התקופות רצות לפי יום מחזור חיוב הניתן להגדרה, לא לפי ה-1 לחודש הקלנדרי — בדיוק כמו שכרטיסי אשראי בישראל מחייבים בפועל.

## מתחת למכסה המנוע

כמה החלטות שכדאי לציין למי שקורא את הקוד:

- **Next.js 16 (App Router) עם TypeScript**, server components ו-route handlers, פרוס על Vercel.
- **Prisma 7 מול PostgreSQL (Supabase)**, בדרך כלל דרך connection pooler, עם "פתח מילוט" מתועד לחיבור ישיר (`PLUX_DIRECT_DB`) לסקריפטים שצריכים טרנזקציה ארוכה אחת ורציפה (למשל סקריפט זריעת נתוני הדמו).
- **בידוד בין משתמשים בלי מדיניות RLS של Postgres**: כל שאילתה רצה בתוך טרנזקציית Prisma שקודם מגדירה `app.current_user_id` ברמת ה-session דרך `set_config(..., true)` — מוגבל לטרנזקציה, לא לחיבור, וזה קריטי מאחורי pooler שבו חיבורים משותפים בין בקשות.
- **בלי `middleware.ts`** — כל route בודק בעצמו את ההרשאה מול Clerk באופן מפורש, כך שלוגיקת ההרשאה נשארת גלויה בנקודת השימוש ולא מרוכזת ומוסתרת.
- **עוזר ה-AI מבוסס tool-calling, לא RAG על גבי בלוב** — ל-Claude יש קבוצה קטנה של כלים מוקלדים (`getMonthlyReport`, `findTransactions`, `listAvailableMonths`) והוא בוחר מה להפעיל; התשובות מבוססות על תוצאות שאילתה אמיתיות, וסיכומים חודשיים נשמרים בקאש כך שהם נוצרים פעם אחת לתקופה, לא בכל טעינת עמוד.
- **גישת דמו דרך sign-in tokens של Clerk**, לא סיסמת דמו משותפת — session אמיתי ומלא של Clerk, שנוצר בצד השרת בכל ביקור מחדש.
- **דפי חשבון/כרטיס שהועלו נמחקים אחרי 30 יום** על ידי משימה מתוזמנת — התנועות המפוענחות נשארות, אבל הקובץ הגולמי (שיכול להכיל מספר תעודת זהות מלא או מספר חשבון) לא נשמר לנצח רק ליתר ביטחון שיהיה צריך לפענח אותו מחדש בעתיד.

תיעוד מלא של כל ה-endpoints — טיפוסי בקשה/תשובה שנקראו ישירות מה-route-ים עצמם, לא סכמה נפרדת שיכולה לסטות — נמצא ב-[`docs/API.md`](./docs/API.md).

## הרצה מקומית

```bash
git clone https://github.com/deni-ing/plux.git
cd plux
npm install
cp .env.template .env  # למלא את הערכים למטה
npx prisma migrate dev
npm run dev
```

מה שצריך:

| משתנה | בשביל מה |
|---|---|
| `DATABASE_URL` / `DIRECT_URL` | מסד נתוני PostgreSQL (פותח מול [Supabase](https://supabase.com/)) |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` / `CLERK_SECRET_KEY` | הרשאה ([Clerk](https://clerk.com/)) |
| `ANTHROPIC_API_KEY` | מפעיל את Pluxer ואת הסיכומים החודשיים |
| `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` | נדרש רק לכמה פעולות ניהול ספציפיות של Supabase |
| `TWELVE_DATA_API_KEY` | אופציונלי — טיקר השוק בדשבורד |

הרשימה המלאה, כולל דריסות אופציונליות, נמצאת ב-`.env.template`.

```bash
npm run test    # טסטים
npm run lint    # ESLint
npm run build   # build לפרודקשן + בדיקת טיפוסים
```

## Prior art

יש לא מעט דרכים שבהן ישראלים כבר עוקבים אחרי ההוצאות שלהם, וכדאי להיות ספציפיים לגבי איך Plux מתייחסת אליהן במקום סתם לנפנף.

**[MAX](https://www.max.co.il/cards/max-app)** (לשעבר לאומי קארד) מציעה אפליקציה נלווית לכרטיסי האשראי שלה: תצוגה מסווגת של החיובים, כמה סיכומי הוצאות, הטבות ותגמולים. זה שימושי בהחלט, אבל זה מוגבל לכרטיסי MAX — האפליקציה לא בנויה לאחד חשבון בנק וכרטיסים מחברות אחרות לתמונה אחת, ואין בה תחזית, זיהוי מנויים, או אפשרות לשאול אותה שאלה.

**[Riseup](https://www.riseup.co.il/)** הוא הדבר הכי קרוב שיש בישראל למוצר ניהול תקציב ייעודי: מתחבר לחשבונות הבנק והכרטיסים שלך, נותן יעד הוצאה שבועי, מחזה את תזרים המזומנים שלך לשארית החודש, ומגובה בצוות תמיכה וקהילה. זה מוצר מוצק ומוערך — וגם מנוי חודשי בעלות ₪55 (אחרי תקופת ניסיון חינם), סגור-קוד, מה שהופך אותו לבלתי נגיש כמשהו ללמוד ממנו או להרחיב.

Plux לא מנסה להחליף אף אחד מהם לשימוש יומיומי אמיתי — זו חקירה מאפס של אותה בעיה בדיוק: מודל מדויק של איך מחזורי חיוב ישראליים באמת עובדים, ממשק צ'אט שבאמת יכול לענות על שאלות לגבי הנתונים שלך במקום רק לגרף אותם, ומשהו שכל אחד יכול לפתוח וללחוץ עליו תוך עשר שניות בלי ליצור חשבון. זה חינמי, ברישיון MIT פתוח, וכל בסיס הקוד כאן לקריאה.
