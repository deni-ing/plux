Plux — הסבר פקודות

מרכז את כל הפקודות שהופיעו בבניית הפרויקט, לפי קטגוריה. כל פקודה מופיעה

פעם אחת, בצורתה הכללית, עם הסבר קצר על מה שהיא עושה ולמה השתמשנו בה.

מוסכמות: <כך> מסמן ערך שמחליפים. הפקודות נכתבו ל-PowerShell על Windows,

מתוך תיקיית הפרויקט C:\Users\danie\source\plux.

1. PowerShell — ניווט וקבצים

dir

מציג את תוכן התיקייה הנוכחית. השתמשנו בו כדי לוודא באיזו תיקייה אנחנו לפני

פקודות שיוצרות קבצים, ולראות אילו קובצי תצורה קיימים בשורש.

dir <קובץ1>, <קובץ2>

בודק קיום של כמה קבצים בבת אחת. מחזיר שגיאה על כל אחד שחסר, וזו הדרך המהירה

לוודא שהעתקה הצליחה.

dir <תיקייה> -Recurse -File | Select-Object -ExpandProperty FullName

מדפיס את הנתיב המלא של כל קובץ בתיקייה ובתת-התיקיות. שימושי כדי לראות בדיוק

מה חולץ מארכיון לפני שמעתיקים אותו לפרויקט.

mkdir <תיקייה>

יוצר תיקייה. עם -Force הפקודה לא נכשלת אם התיקייה כבר קיימת.

move <מקור> <יעד>

מעביר קובץ. השתמשנו בו כדי להעביר קובץ בודד מתיקיית ההורדות לפרויקט.

Copy-Item <מקור> <יעד> -Force

מעתיק קובץ ודורס קיים. חשוב: עם תיקיות ו--Recurse הפקודה הזו **אינה

ממזגת** לתוך תיקייה קיימת אלא מעתיקה אותה לתוכה, ויוצרת קינון כמו

lib\lib\db. לתיקיות השתמשנו ב-robocopy.

Rename-Item <קובץ> <שם חדש>

משנה שם. נדרש כשווינדוס שומר הורדה חוזרת בשם plux-parser (1).zip והפקודות

מצביעות לשם הנקי.

Remove-Item <נתיב> -Force

מוחק קובץ. -Recurse מוחק תיקייה על תוכנה, ו--ErrorAction SilentlyContinue

מונע שגיאה כשהקובץ ממילא לא קיים — שימושי בפקודות ניקוי.

Get-ChildItem <תבנית> | Sort-Object LastWriteTime -Descending | Select-Object -Skip 1 | Remove-Item -Force

מוחק את כל הקבצים התואמים חוץ מהחדש ביותר. -Skip 1 הוא הלב — בלעדיו זה מוחק

גם את זה שרצית לשמור.

**$files = (Get-ChildItem $HOME\Downloads\export.xlsx).FullName**

אוסף נתיבים לתוך משתנה. PowerShell מפרק מערך לארגומנטים נפרדים אוטומטית, ולכן

אפשר להעביר $files לסקריפט וכל הקבצים יגיעו כארגומנטים — גם אם יש רווחים בשמות.

המשתנה מתאפס עם כל חלון טרמינל חדש.

2. PowerShell — ארכיונים והעתקה לפרויקט

Expand-Archive <קובץ.zip> -DestinationPath <תיקייה> -Force

מחלץ ארכיון. -Force דורס חילוץ קודם באותה תיקייה.

robocopy <מקור> . /E /IS

מעתיק עץ תיקיות שלם וממזג לתוך היעד במקום ליצור קינון. /E כולל

תת-תיקיות ריקות, /IS דורס גם קבצים שנראים לו זהים. מסיים בקוד יציאה 1

בהצלחה — אצלו 0 פירושו "לא היה מה להעתיק".

הרצף המלא שחזר לאורך הפרויקט:

Remove-Item $HOME\Downloads\<שם> -Recurse -Force -ErrorAction SilentlyContinue
Expand-Archive $HOME\Downloads\<שם>.zip -DestinationPath $HOME\Downloads\<שם> -Force
robocopy $HOME\Downloads\<שם> . /E /IS
Select-String -Path <קובץ שהועתק> -Pattern "<מילה חדשה>" -SimpleMatch

מוחק חילוץ ישן, מחלץ, ממזג לפרויקט, ומאמת שהקוד באמת הגיע. השורה האחרונה

היא זו שחסכה סבבים שלמים.

3. PowerShell — קריאה ואימות

type <קובץ>

מדפיס את תוכן הקובץ. הכינוי של Get-Content.

Get-Content <קובץ> -TotalCount <N>

מדפיס רק את N השורות הראשונות.

Get-Content <קובץ> -Raw

קורא את הקובץ כמחרוזת אחת ולא כמערך שורות. נדרש לביטויים רגולריים שפורשים על

כמה שורות — אבל שים לב ש-^ אז מתייחס לתחילת המחרוזת כולה, לא לתחילת שורה.

Add-Content <קובץ> "<טקסט>"

מוסיף שורה לסוף קובץ. השתמשנו בו כדי להוסיף חריג ל-.gitignore.

(Get-Item <קובץ>).Length

מחזיר את גודל הקובץ בבתים.

Get-FileHash <קובץ> -Algorithm SHA256 | Format-List

מחשב טביעת אצבע של הקובץ. משמש לוודא שהקובץ על הדיסק זהה לזה שנשלח.

מגבלה: גיבוב שונה אומר "לא זהה" ולא מה שונה — סופי שורה שהומרו

ל-CRLF ייתנו גיבוב שונה לקובץ תקין.

Select-String -Path <קובץ> -Pattern "<טקסט>" -SimpleMatch

מחפש מחרוזת בקובץ ומדפיס את השורות התואמות. -SimpleMatch מבטל פירוש כביטוי

רגולרי. זו הדרך העדיפה לוודא גרסת קוד: חיפוש מילה שקיימת רק בגרסה החדשה

עונה ישירות על "ישן או חדש", ואינו רגיש לסופי שורה.

<פקודה> 2>&1 | Select-String -Pattern "<תבנית>"

מסנן פלט ארוך ומשאיר רק שורות מעניינות. 2>&1 מפנה גם את פלט השגיאות לצינור.

אזהרה: הצינור שובר קידוד UTF-8, וטקסט עברי יוצא משובש.

4. PowerShell — סודות ומחרוזות

-join ((48..57)+(65..90)+(97..122) | Get-Random -Count 48 | % {[char]$_})

מייצר מחרוזת אקראית באורך 48 מאותיות וספרות בלבד. שימש ליצירת CRON_SECRET.

ללא תווים מיוחדים, כדי שלא יישבר בכותרות או במחרוזות חיבור.

(Select-String -Path .env -Pattern 'URL').Line -replace '(://[^:]+:)[^@]+(@)','$1*$2'**

מדפיס את שורות מחרוזות החיבור עם הסיסמה מוחלפת ב-***. מאפשר לבדוק שם

משתמש, מארח ופורט בלי לחשוף את הסוד — וכך גילינו ש-DIRECT_URL הצביע לתפקיד

הלא נכון.

([regex]'<תבנית>').Match((Get-Content .env -Raw)).Groups[1].Value

שולף ערך יחיד מקובץ לפי קבוצת לכידה. השתמשנו בו כדי לקרוא את CRON_SECRET

לתוך משתנה בלי להדפיס אותו.

5. Git

git config --global user.name "<שם>" / git config --global user.email "<מייל>"

קובע את הזהות שנצרבת בכל commit. הפרטים נחשפים אם הריפו ציבורי.

git init

מאתחל ריפו. על ריפו קיים הוא מדפיס Reinitialized ואינו הורס דבר.

git add .

מוסיף את כל השינויים לאזור ההכנה.

git status --short

מציג רשימה קצרה של שינויים: A חדש, M שונה, ?? לא מנוהל. **זו נקודת

העצירה לפני כל commit** — הרגע היחיד שבו קל למנוע סוד שנכנס להיסטוריה.

git commit -m "<הודעה>"

שומר את מה שבאזור ההכנה.

git push

דוחף לשרת המרוחק.

git log --oneline

מציג את ההיסטוריה בשורה לכל commit. -2 מגביל למספר האחרונים. הסימון

(HEAD -> main, origin/main) מראה שהמקומי והמרוחק מסונכרנים.

git ls-files

מדפיס את כל הקבצים המנוהלים בגיט, לא רק את השינויים. כך בדקנו שאין

דפי חשבון או קובצי אקסל בהיסטוריה.

git check-ignore -v <קובץ>

עונה האם הקובץ חסום ולפי איזה כלל. תשובה ישירה מהמנגנון במקום הנחה —

פלט כמו .gitignore:34:.env* הוא אישור, ושתיקה אומרת שהקובץ אינו חסום.

git checkout -- <קובץ>

מחזיר קובץ למצב השמור האחרון. שימש כשקובץ נמחק או נדרס בטעות.

git status --porcelain

פלט קבוע לעיבוד אוטומטי. משמש בתוך doctor כדי לדעת אם עץ העבודה נקי.

git rev-list --count @{u}..HEAD

מספר ה-commits שקיימים מקומית ולא נדחפו. 0 פירושו שהכל אצל השרת.

7. Prisma CLI

npx prisma migrate dev

מחיל מיגרציות שטרם הוחלו, ואם יש פער בין הסכימה למסד — יוצר מיגרציה חדשה.

מדפיסה רק את המיגרציות שהיא הריצה, לא את כל הרשימה.

npx prisma migrate dev --name <שם>

כנ״ל, עם שם מפורש למיגרציה שתיווצר.

npx prisma migrate dev --create-only --name <שם>

יוצר תיקיית מיגרציה בלי להריץ אותה. זו הדרך הנכונה להוסיף SQL ידני

שהסכימה לא יודעת עליו — Prisma נותנת חותמת זמן תקינה ואין צורך לחשב תאריכים.

npx prisma migrate status

משווה בין תיקיית migrations/ לטבלת ההיסטוריה במסד ומדווח על פערים.

משתמשת ב-DIRECT_URL, ולכן היא גם הבדיקה הנכונה לחיבור המיגרציות.

npx prisma migrate reset

הורס. מוחק את כל הטבלאות ואת טבלת ההיסטוריה, ובונה מחדש מהמיגרציות בלבד.

בפרויקט הזה הריצה שלו גם הוכיחה שההיסטוריה שלמה ורפרודוקטיבית.

npx prisma generate

מייצר את לקוח Prisma מהסכימה אל lib/generated.

9. SQL — תפקידים והרשאות

CREATE ROLE plux_app NOLOGIN NOBYPASSRLS NOCREATEDB NOCREATEROLE NOSUPERUSER;

יוצר תפקיד ייעודי לאפליקציה. NOBYPASSRLS הוא הלב — בלעדיו התפקיד מתעלם

מכל מדיניות RLS, בשקט. נוצר עם NOLOGIN כדי שהסיסמה תיקבע בנפרד ולא תיכנס

לקובץ מיגרציה שנשמר בגיט.

ALTER ROLE plux_app WITH LOGIN PASSWORD '<סיסמה>';

מפעיל כניסה וקובע סיסמה. פקודה חד-פעמית — מריצים, דורסים את הטקסט, ולא

שומרים את השאילתה.

GRANT USAGE ON SCHEMA public TO plux_app;

מתיר לתפקיד לגשת לסכימה. בלי זה אין גישה לשום טבלה שבתוכה.

GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO plux_app;

נותן הרשאות נתונים בלבד. אין CREATE, אין ALTER, אין DROP — ולכן

באג בקוד האפליקציה אינו יכול להרוס מבנה.

GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO plux_app;

מתיר שימוש במונים אוטומטיים, שנדרשים להכנסת שורות.

ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ... TO plux_app;

מחיל את ההרשאות גם על טבלאות שייווצרו בעתיד. בלי זה, כל מודל חדש נראה

לאפליקציה כאילו אינו קיים — והשגיאה תהיה "אין הרשאה", לא "טבלה חסרה".

SELECT rolname, rolcanlogin, rolbypassrls FROM pg_roles WHERE rolname = '<תפקיד>';

בודק שהתפקיד קיים, האם הוא יכול להתחבר, והאם הוא עוקף RLS.

SELECT current_user, (SELECT rolbypassrls FROM pg_roles WHERE rolname = current_user);

עונה על השאלה הקריטית: באיזה תפקיד אני מחובר עכשיו, והאם הוא עוקף RLS.

זו השאילתה שחשפה שה-RLS כלל לא נאכף.

10. SQL — Row Level Security

CREATE OR REPLACE FUNCTION plux_current_user_id() ... SELECT NULLIF(current_setting('app.current_user_id', true), '')

קוראת את זהות המשתמש שנקבעה לטרנזקציה. ה-true אומר "אל תזרוק שגיאה אם לא

הוגדר", ואז מוחזר NULL — וכל השוואה ל-NULL אינה אמת. **ברירת המחדל היא

לא לראות כלום.**

ALTER TABLE <טבלה> ENABLE ROW LEVEL SECURITY;

מדליק את המנגנון על הטבלה.

ALTER TABLE <טבלה> FORCE ROW LEVEL SECURITY;

מחיל את המדיניות גם על בעל הטבלה, שאחרת פטור ממנה. **אינו משפיע על

תכונת BYPASSRLS של תפקיד** — אלה שני מנגנוני עקיפה שונים, וצריך לסגור את

שניהם.

CREATE POLICY <שם> ON <טבלה> FOR ALL USING (...) WITH CHECK (...);

החוק עצמו. USING שולט במה שרואים (קריאה, עדכון, מחיקה), WITH CHECK שולט

במה שכותבים. בלי השני אפשר לקרוא רק את שלך אבל לשתול נתונים אצל אחרים.

SELECT set_config('app.current_user_id', <ערך>, true);

קובע את זהות המשתמש לטרנזקציה. ה-true הופך אותו ל-SET LOCAL, כלומר

מתאפס ב-COMMIT. קריטי מאחורי pooler: SET רגיל היה נשאר על החיבור,

והבקשה הבאה הייתה יורשת את זהות המשתמש הקודם.

**SELECT c.relname, c.relrowsecurity, c.relforcerowsecurity, (SELECT count(*) FROM pg_policy p WHERE p.polrelid = c.oid) FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace WHERE n.nspname = 'public' AND c.relkind = 'r';**

מדווח לכל טבלה: האם RLS דלוק, האם הוא כפוי, וכמה מדיניות יש עליה. משמש

ב-doctor כדי לתפוס טבלה חדשה שנוספה לסכימה ונשכחה ב-RLS.

11. SQL — בדיקות ותחזוקה

**SELECT (SELECT count() FROM transactions) AS txns, (SELECT count() FROM accounts) AS accounts, (SELECT count(*) FROM import_jobs) AS jobs;**

שלוש ספירות בשאילתה אחת. כך אימתנו שייבוא חוזר של אותו קובץ אינו מכפיל

שורות — 169 תנועות מול שלוש משימות ייבוא.

SELECT "fileName", "storagePath", "startedAt" FROM import_jobs ORDER BY "startedAt" DESC LIMIT 3;
