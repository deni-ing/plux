Plux — מילון מושגים

כל מונח שהופיע בבניית הפרויקט, בשתי שורות או פחות, בשפה פשוטה.

מסודר לפי נושא. לחיפוש מהיר: Ctrl+F.

1. הכלים והשירותים

Node.js

תוכנה שמריצה קוד JavaScript מחוץ לדפדפן. בלעדיה, JavaScript יודע לרוץ רק בתוך אתר.

npm

מנהל החבילות של Node — מוריד ספריות קוד שאחרים כתבו. כמו חנות אפליקציות, לקוד.

npx

מריץ כלי מ-npm בלי להתקין אותו קבוע. npx prisma = "תריץ את prisma הפעם".

TypeScript

JavaScript עם בדיקת טיפוסים. אתה מצהיר "המשתנה הזה הוא מספר", והמחשב צועק אם שמת שם טקסט — לפני שהקוד רץ.

React

ספרייה לבניית ממשקי משתמש מרכיבים קטנים. כל כפתור, כרטיס או טופס הוא "רכיב" שאפשר לעשות בו שימוש חוזר.

Next.js

מסגרת עבודה מעל React שמוסיפה שרת, ניתוב עמודים ו-API. באפליקציה שלנו היא גם הצד שרואים וגם הצד שרץ בשרת.

Tailwind

ספריית עיצוב שבה כותבים סגנון ישירות בתוך ה-HTML במחלקות קצרות, למשל p-6 לריווח.

PowerShell

שורת הפקודה של Windows. החלון השחור שבו אתה מקליד פקודות במקום ללחוץ בעכבר.

VS Code

עורך הקוד. שם אתה כותב ועורך קבצים.

Git

מערכת שעוקבת אחרי כל שינוי בקוד ומאפשרת לחזור אחורה. כמו "היסטוריית גרסאות" של גוגל דוקס, אבל אתה שולט מתי נשמרת נקודה.

GitHub

אתר שמאחסן ריפוזיטוריז של Git באינטרנט. שם הקוד שלך שמור גם אם המחשב נעלם.

Vercel

שירות שמארח את האתר. הוא מושך את הקוד מגיטהאב, בונה אותו, ומעלה לאוויר — אוטומטית בכל דחיפה.

Supabase

שירות שנותן מסד נתונים PostgreSQL בענן, ובנוסף אחסון קבצים. אתה לא מתחזק שרת.

Clerk

שירות שמנהל משתמשים — הרשמה, התחברות, סיסמאות. במקום לבנות מסך התחברות מאפס.

PostgreSQL

תוכנת מסד הנתונים עצמה. אחת הנפוצות והחזקות בעולם, וחינמית.

Prisma

שכבה שמתרגמת בין קוד TypeScript לבין SQL. אתה כותב db.transaction.count() והיא מייצרת את השאילתה.

unpdf

ספרייה שמחלצת טקסט מקובצי PDF.

2. מסד נתונים — היסודות

מסד נתונים

מקום מסודר לשמור מידע שנשאר גם אחרי שהתוכנה נסגרת. לא קובץ אחד גדול, אלא מערכת שיודעת לחפש ולעדכן ביעילות.

טבלה

כמו גיליון אקסל: שורות ועמודות. transactions היא טבלה שכל שורה בה היא תנועה אחת.

שורה

פריט בודד בטבלה. תנועה אחת, משתמש אחד, חשבון אחד.

עמודה

שדה בשורה. amount, merchant, bookedAt הן עמודות.

סכימה

המבנה: אילו טבלאות יש, אילו עמודות בכל אחת, ומאיזה סוג. אצלנו היא כתובה בקובץ schema.prisma.

SQL

שפת השאילתות של מסדי נתונים. SELECT count(*) FROM transactions = "כמה שורות יש בטבלת התנועות".

מפתח ראשי

עמודה שמזהה שורה באופן ייחודי. אצלנו id.

מפתח זר

עמודה שמצביעה לשורה בטבלה אחרת. accounts.userId מצביע ל-users.id — ולכן אי אפשר ליצור חשבון למשתמש שלא קיים.

אינדקס

מבנה עזר שמאיץ חיפוש, כמו אינדקס בסוף ספר. בלעדיו המסד עובר על כל השורות.

אילוץ ייחודיות

כלל שאוסר על שתי שורות להיות זהות בשדות מסוימים. אצלנו על (userId, dedupHash, occurrence) — וזה מה שמונע ייבוא כפול.

enum

רשימה סגורה של ערכים אפשריים. direction יכול להיות רק DEBIT או CREDIT, ולא כל טקסט.

Decimal מול float

float הוא מספר עשרוני מקורב, ולכן 0.1 + 0.2 אינו בדיוק 0.3. בכסף משתמשים ב-Decimal או בשלמים, כי אגורה אחת של סטייה שוברת אימות.

3. מסד נתונים — פעולות

שאילתה

בקשה למסד: תן לי, הוסף, עדכן, מחק.

טרנזקציה

קבוצת פעולות שמתבצעות כיחידה אחת. או שכולן הצליחו, או שאף אחת לא — אין מצב באמצע.

COMMIT

סיום מוצלח של טרנזקציה. מכאן השינויים קבועים.

upsert

"עדכן אם קיים, צור אם לא". חוסך בדיקה נפרדת.

skipDuplicates

בהכנסה מרובה — דלג בשקט על שורות שמפרות אילוץ ייחודיות במקום להיכשל.

מיגרציה

קובץ SQL שמשנה את מבנה המסד, עם סדר קבוע. מריצים אותם אחד אחרי השני וכל מסד מגיע לאותו מבנה.

checksum

טביעת אצבע של תוכן קובץ. Prisma שומרת אותה לכל מיגרציה, ולכן עריכה של מיגרציה שכבר רצה נתפסת.

seed

נתוני התחלה שנטענים למסד — למשל רשימת קטגוריות ברירת מחדל.

4. אבטחת מסד

תפקיד (role)

"משתמש" של מסד הנתונים. לא בן אדם, אלא זהות שהתוכנה מתחברת בה, עם הרשאות משלה.

הרשאות / GRANT

מה מותר לתפקיד לעשות. אצלנו plux_app יכול לקרוא ולכתוב שורות, אבל לא ליצור או למחוק טבלאות.

RLS — Row Level Security

כלל שהמסד עצמו אוכף: החזר רק שורות ששייכות למשתמש הנוכחי. גם אם הקוד ישכח לסנן, המסד לא יראה לו את השאר.

מדיניות (policy)

החוק הקונקרטי של RLS על טבלה מסוימת. למשל: "רק שורות שבהן userId שווה למשתמש הנוכחי".

USING מול WITH CHECK

USING שולט במה שאתה רואה. WITH CHECK שולט במה שאתה כותב — מונע ממך לשתול שורה בשם מישהו אחר.

FORCE ROW LEVEL SECURITY

מחיל את המדיניות גם על בעל הטבלה, שאחרת פטור ממנה.

BYPASSRLS

תכונה של תפקיד שגורמת לו להתעלם מכל מדיניות RLS — בשקט, בלי שגיאה. FORCE אינו מטפל בה, ולכן צריך תפקיד נפרד שאין לו אותה.

service_role

מפתח של Supabase שעוקף כל הרשאה. שרת בלבד, ולעולם לא בקוד שמגיע לדפדפן.

5. חיבור למסד

מחרוזת חיבור (connection string)

כתובת מלאה למסד בשורה אחת: משתמש, סיסמה, מארח, פורט ושם מסד.

pooler / בריכת חיבורים

מתווך שמחזיק מספר חיבורים פתוחים ומשאיל אותם לבקשות. חיבור למסד יקר לפתוח, ובסביבה סרברלס נפתחים המון.

transaction mode

מצב שבו ה-pooler מחזיר את החיבור לבריכה בסוף כל טרנזקציה. יעיל, אבל אומר שהחיבור הבא עלול לקבל אותו חיבור פיזי.

SET מול SET LOCAL

SET נשאר על החיבור גם אחרי הטרנזקציה. SET LOCAL מתאפס ב-COMMIT. מאחורי pooler ההבדל הזה הוא ההבדל בין בידוד לדליפת נתונים בין משתמשים.

DATABASE_URL מול DIRECT_URL

אצלנו: הראשון הוא חיבור האפליקציה דרך ה-pooler, השני הוא חיבור ישיר למיגרציות. שני תפקידים שונים, שתי רמות הרשאה.

6. ווב ואפליקציה

שרת מול לקוח

"לקוח" הוא הדפדפן של המשתמש, "שרת" הוא המחשב המרוחק. סודות חיים בשרת בלבד.

API

נקודת כניסה שהקוד פונה אליה במקום בן אדם. אצלנו /api/imports מקבל קובץ ומחזיר תשובה.

route

נתיב באתר, ומה שקורה כשפונים אליו. /import מציג מסך, /api/imports מקבל נתונים.

HTTP

הפרוטוקול שבו דפדפן ושרת מדברים.

GET מול POST

GET מבקש מידע, POST שולח מידע. העלאת קובץ היא POST.

קוד סטטוס

מספר שאומר איך הבקשה הסתיימה. 200 הצליח, 401 לא מזוהה, 403 אין הרשאה, 500 תקלה בשרת, 503 השירות לא זמין כרגע.

multipart/form-data

פורמט לשליחת קבצים ב-HTTP. זה מה שהדפדפן שולח כשמעלים קובץ.

middleware / proxy

קוד שרץ על כל בקשה לפני שהיא מגיעה לנתיב עצמו. אצלנו הוא זה שמאפשר לזהות את המשתמש. ב-Next.js 16 הקובץ נקרא proxy.ts.

דינמי מול סטטי

עמוד סטטי נבנה מראש וזהה לכולם. עמוד דינמי נבנה בכל בקשה — נדרש כשהתוכן תלוי במי שמחובר.

serverless

קוד שרץ רק כשקוראים לו, ומכובה בין בקשות. זול וגמיש, אבל אין לו זיכרון בין קריאות.

deploy / דיפלוי

העלאת גרסה חדשה לאוויר.

build מול dev

dev מריץ שרת פיתוח מהיר וסלחני. build בונה גרסת ייצור מלאה עם בדיקת טיפוסים — וזה מה שהשרת מריץ.

cron

תזמון להרצה אוטומטית. 0 3 * * * = כל יום ב-03:00.

signed URL

קישור זמני לקובץ פרטי, שפג אחרי זמן קצוב. מאפשר גישה בלי לפתוח את האחסון לכולם.

bucket / דלי

תיקייה עליונה באחסון בענן. אצלנו statements, והוא פרטי.

7. סביבה וסודות

משתנה סביבה

ערך שמוגדר מחוץ לקוד ונקרא ממנו. כך סיסמאות לא נכתבות בקובץ שנשמר בגיט.

.env

הקובץ שמחזיק את משתני הסביבה מקומית. חסום בגיט תמיד.

NEXT_PUBLIC_

קידומת שאומרת ל-Next להטמיע את הערך בקוד שנשלח לדפדפן. מתאימה למפתח פומבי, והרסנית על סוד.

.gitignore

רשימת קבצים שגיט מתעלם מהם. שם נמצא .env.

סיבוב סוד (rotation)

החלפת סוד שנחשף. חובה לעדכן בכל מקום שבו הוא חי — מקומי, Vercel, וכל השאר.

8. קוד ומודולים

מודול

קובץ קוד. import מביא ממנו דברים, export מוציא החוצה.

ESM מול CommonJS

שתי שיטות ייבוא. החדשה משתמשת ב-import, הישנה ב-require. ערבוב ביניהן הוא מקור נפוץ לשגיאות טעינה.

alias (@/)

קיצור נתיב. @/lib/parsers פירושו "מהשורש", במקום לספור ../../.

linter / ESLint

כלי שמסמן קוד בעייתי לפני שהוא רץ — משתנה שלא בשימוש, ייבוא חסר.

regex / ביטוי רגולרי

שפה קצרה לתיאור תבנית בטקסט. \d{2}\.\d{2}\.\d{4} מתאר תאריך בצורה 20.08.2026.

hash / SHA-256

פונקציה שהופכת תוכן למחרוזת קבועת אורך. אותו קלט תמיד ייתן אותו פלט, ושינוי זעיר ישנה הכל.

JSON

פורמט טקסט להעברת נתונים מובנים. זה מה שה-API מחזיר.

XML

פורמט טקסט עם תגיות. קובץ xlsx בנוי ממנו.

ZIP

פורמט ארכיון דחוס. קובץ xlsx הוא בעצם ZIP עם קובצי XML בפנים.

UTF-8

שיטת קידוד שמאפשרת עברית ואמוג'י. רוב תקלות ה"ג'יבריש" הן קידוד לא תואם.

תווי בקרה דו-כיווניים

תווים בלתי נראים שקובעים כיוון טקסט מעורב עברית-אנגלית. הם נספרים כתווים ושוברים ביטויים רגולריים שלא מנקים אותם.

RTL / dir="rtl"

כיוון מימין לשמאל. קובע איפה מתחיל טקסט ולאיזה צד "התחלה" מתייחסת בעיצוב.

9. Git — מונחים

repository / ריפו

תיקיית הפרויקט על כל היסטוריית השינויים שלה.

commit

נקודת שמירה עם הודעה. יחידת ההיסטוריה של גיט.

branch / ענף

קו פיתוח נפרד. main הוא הראשי.

remote / origin

העותק המרוחק. origin הוא השם המוסכם לגיטהאב.

push / pull

push דוחף שינויים מקומיים למרוחק, pull מושך משם.

staging area / אזור הכנה

מה שייכנס ל-commit הבא. git add מכניס לשם.

working tree / עץ עבודה

הקבצים כפי שהם על הדיסק כרגע.

10. מושגים של הפרויקט עצמו

דוח / statement

הקובץ שהמשתמש מוריד מהבנק או מחברת האשראי.

פרסר

קוד שקורא קובץ בפורמט מסוים ומוציא ממנו נתונים מובנים.

dedupHash

טביעת אצבע של תנועה, בנויה משדות שלא משתנים. מאפשרת לזהות שאותה עסקה כבר קיימת, גם אם הסטטוס שלה השתנה.

occurrence

מספר סידורי לתנועות זהות באמת באותו יום — למשל ארבע קניות ממכונת שתייה. מאפשר לשמור את כולן בלי להפר את אילוץ הייחודיות.

CARD_SETTLEMENT

שורת החיוב המרוכז של כרטיס האשראי בדף הבנק. אותו כסף שכבר מפורט בקובץ חברת האשראי.

countsAsSpending

דגל שאומר אם התנועה נספרת כהוצאה. כבוי בחיובי אשראי ובהעברות, כדי לא לספור פעמיים.

reconciled

האם הייבוא הצליח לאמת את עצמו מול מה שהספק הצהיר. false אינו כישלון — הנתונים נכנסו, רק בלי אישור.

ImportJob

רשומה שמתעדת העלאה אחת: איזה קובץ, מתי, כמה שורות נכנסו וכמה דולגו.

שרשרת יתרות

בדף חשבון יש יתרה מצטברת בכל שורה, ולכן ההפרש בין יתרות שכנות חייב להיות הסכום של השורה. מאפשר לאמת כל תנועה בנפרד.

withUser

הפונקציה שדרכה כל גישה לנתוני משתמש עוברת. פותחת טרנזקציה וקובעת בה את זהות המשתמש עבור RLS.

doctor

סקריפט הבדיקה של הפרויקט. עובר על סביבה, קבצים, מסד, פרסרים וגיט בפקודה אחת.

11. שלושה מושגים ששווים משפט נוסף

מה זה בעצם "בידוד משתמשים"

שכל משתמש יראה רק את הנתונים שלו. נשמע מובן מאליו, אבל במסד אחד עם טבלה אחת שבה כל השורות מעורבבות — זה משהו שצריך לאכוף אקטיבית.

למה מיגרציה ולא "פשוט לשנות את הטבלה"

כי צריך שאותו שינוי יקרה גם אצלך, גם בייצור, וגם אצל מישהו שיצטרף מחר. מיגרציה היא מתכון שאפשר להריץ שוב.

למה "אימות" ולא "בדיקה שהקוד לא נפל"

קוד יכול לרוץ עד הסוף ולהחזיר מספר שגוי. אימות משווה את מה שחישבת למה שהמקור הצהיר — וזה מה שתופס שגיאה שקטה.
